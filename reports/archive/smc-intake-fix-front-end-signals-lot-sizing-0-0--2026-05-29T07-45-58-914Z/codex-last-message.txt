1. **Objective**

Blocked the frontend from treating backend-authored sub-`0.01` stage lots as executable while preserving backend authority. Branch: `codex/smc-intake-fix-front-end-signals-lot-sizing-0-0-`. PR: https://github.com/klintaruvinga-png/smcsmartfib-WebApp/pull/280

2. **Root cause / analysis**

`isTradePlanComplete()` only checked TP/RR completeness, and the plan card rendered any finite lot value plus enabled `Send to execution` off `backendConfirmed && planComplete`. That let backend lots like `0.0` and `0.009` look actionable even though the PHP queue already skips stages below `0.01`.

3. **Patch plan**

Kept the patch frontend-only:
- add a shared staged-lot executability helper
- use it in the plan card for warning, display state, and CTA disablement
- pin the failure path in the existing plan-page test file
- leave backend math, queue behavior, and request payload unchanged
