**1. Objective**

Fix the live-signals poll path so repeated `/live-signals` responses stay observable to the frontend without changing backend signal identity, candle anchoring, execution deduplication, or stale-data authority.

**2. Root cause / analysis**

Confirmed root cause was the route contract, not signal math. `get_live_signals()` returned cached snapshot signals with stable `id` and `createdAt` and no response-time field, so repeated polls could be structurally identical when candle time and direction were unchanged.

One contract ambiguity existed in the PHP test harness: making `rest_ensure_response()` fully wrap arrays would have broken unrelated legacy route tests. I resolved that with an opt-in response wrapper used only by the new `/live-signals` regression.

**3. Patch plan**

Add the failing route-level regression first, patch `get_live_signals()` surgically, mirror the optional transport field in app/SDK types, write the required implementation/report artifacts, then run the contract validations and publish the branch/PR.
